# AnyToFire

本项目 AnyToFire 的功能包含：任意网的游戏档案保存与本地合并、任意网自动同步具体成绩至 FireNet，以及旧 IIDXScore 插件的全部功能（包括 Omnifix 分数本地保存与游戏内显示）。

## 使用前准备

使用火网打开 IIDX 并创建档案，在软件内填入 Firenet **第三方访问码**。

安装时将发布包中的 `AnyToFire` 文件夹放到 IIDX 根目录，运行 `AnyToFire\AnyToFire.exe`。DLL、EXE 与 WebView2Loader.dll 位于同一文件夹；程序会使用游戏根目录中已有的成绩数据库、导出、设置和曲库文件。旧版根目录中的 `AnyToFire.dll` 不再需要注入，启动软件会将原注入项迁移到 `AnyToFire\AnyToFire.dll`。

当前 DLL 支持 IIDX 33 的 0331、0422、0909，以及 IIDX 34 的 0916、010-0917 和 010-1013。各版本使用独立签名，保留旧版本支持；未知构建不会安装钩子。以上六份 DLL 的五组成绩接口与方法表均通过离线装载验证；1013 的实际登录、打歌、结算和上传仍需实机确认。

## 推荐：自动同步

挂载 DLL、填写访问码并开启自动同步后，符合条件的每局成绩会自动上传。无需上传游戏档案，也无需手动上传最近游玩分数。上传成功的单局会标记“已上传”；再次手动上传前会提示确认。omni 等不支持的曲目不会上传。

## 慎用：档案同步

设置中的“Omnifix 分数不上传服务器，只存于本地”默认开启，下次启动游戏时生效。插件用已校验的当前 AC 索引按曲目和谱面判断；确认属于非 AC 的单局先保存至兼容 IIDXScore 的本地库，并采集到最近游玩分数，再在原生 `music.reg` 组包回调中阻止网络发送。此开关同时约束当前 EA 服务器的原生提交；FireNet 自动/手动上传原本也会过滤这些曲目。AC 成绩正常提交。拦截会写入日志，不会伪造“服务器上传成功”；游戏如何展示未发送状态仍需实机验证。

游戏档案只保存每张谱面的最优成绩，无法还原每次游玩的分数与时间，也无法准确记录游玩次数。

单局上传若显示 400/404，请悬停在同步状态上查看服务端错误码与字段。中途死亡记录的 `CONFLICTING_PLAY_LOG` 是火网对游戏原始包的校验冲突；客户端会保留原始成绩，等待服务端兼容。详见 [错误排查](docs/firenet-upload-errors.md)。

列表支持点击表头切换升序／降序，选择状态在排序后保留。

设置中的“开启同一档案自动合并”默认关闭。开启后，同一服务器地址、同一 IIDX ID、同一曲库索引的原始档案会自动生成并维护一份合并结果；合并成功后，原档案自动移入 `.deleted` 并从列表移除，列表只保留合并结果；后续新档案继续并入该结果。身份不明、服务器不同或曲库不同的档案不会自动合并。EX Score 和灯取最高，BP 取最低。

“自动更新”默认开启。软件启动时在后台检查本项目最新正式 GitHub Release，下载 `AnyToFire-v版本.zip` 和对应 `.zip.sha256` 并校验 SHA-256。退出游戏与软件后，自动备份并替换 EXE、DLL 和 WebView2 加载器，保留配置、成绩、SQLite 与曲库索引。安装失败会尝试恢复旧二进制文件，详情写入安装目录的 `update.log`。关闭自动更新会取消尚未安装的更新。

发布时须同时上传 `build.ps1` 生成的 ZIP 和同名 `.zip.sha256` 校验文件；缺失校验文件时更新器不会安装。

0.3.9 提供 1013 兼容。0.3.9 修复更新请求未配置 HTTPS TLS 后端的问题；0.3.7 及更早版本需手动升级一次，此后可在启动时自动检查新版。自动更新只替换 AnyToFire 自身的三个程序文件，不更新 GSM、Playlister 或 Recorder。
